# Switcher

Утилита для macOS, которая автоматически исправляет текст, набранный не в той раскладке клавиатуры — без горячих клавиш и ручного переключения.

```
ghbdtn  →  привет   (набрано в EN, нужно было RU)
ye,kf   →  яблоко
lbdfy   →  диван
```

---

## Возможности

- **Автопереключение** — распознаёт слово, набранное не в той раскладке, языковой моделью, а не жёсткими правилами, и заменяет его сразу после пробела или Enter
- **Двойной Shift** — отменяет последнюю автоматическую замену, если она была не более 5 секунд назад
- **Правила исправления опечаток** — например, `чтото → что-то`, работают независимо от раскладки
- **Обучение** — при отмене двойным Shift слово добавляется в исключения и больше не переключается автоматически
- **Исключения по приложениям** — автопереключение можно отключить для конкретных программ (редакторы кода, терминалы)
- **Словарь исключений** — слова, которые никогда не нужно переключать; поддерживает импорт/экспорт JSON и plain text

## Сборка

### Требования

- macOS 14 Sonoma или новее
- Xcode Command Line Tools:
  ```bash
  xcode-select --install
  ```

### Команды Make

```bash
# Собрать release-бандл, подписать ad-hoc и запустить
make run

# Только собрать .app (без запуска)
make bundle

# Только компиляция в debug-режиме
swift build

# Удалить артефакты сборки и .app
make clean
```

После `make bundle` в корне проекта появляется `Switcher.app`. Приложение подписывается ad-hoc подписью (`codesign --sign -`) — для локального использования Apple Developer аккаунт не нужен.

### Разрешения

При первом запуске macOS потребует разрешение **Специальные возможности**:

1. Системные настройки → Конфиденциальность и безопасность → Специальные возможности
2. Добавить `Switcher.app` в список

Без этого разрешения event tap не создаётся и приложение ничего не делает.

### Иконка

`Resources/AppIcon.icns` уже включена в репозиторий. Для перегенерации:

```bash
swift Resources/generate-icon.swift
```

Скрипт использует AppKit и `iconutil` — создаёт все размеры (16–1024 px) из одного нарисованного шаблона.

## Как это работает

### Event tap

Приложение регистрирует системный `CGEventTap` на уровне сессии (`.cgSessionEventTap`, режим `.headInsertEventTap`) на **собственном выделенном потоке** — это отдельно от главного потока приложения, чтобы занятость UI никогда не приводила к отключению tap'а системой по таймауту и заморозке ввода. Сам tap ничего не блокирует: он разбирает нажатие, кладёт его в буфер и сразу возвращает управление, а событие клавиатуры всегда пропускается дальше без изменений — Switcher никогда не глотает нажатия, он только исправляет уже напечатанное задним числом.

Вся работа, которая может подождать миллисекунды — обращения к Accessibility, проверка орфографии, сама замена — выполняется отдельно, на фоновой очереди.

### Алгоритм автопереключения

```
клавиша нажата
    │
    ├─ буква / знак препинания → добавить в буфер (граница слова — ТОЛЬКО пробел)
    │
    ├─ backspace → убрать последний символ из буфера
    │
    ├─ пробел / Enter  ←── слово закончено
    │       │
    │       ├─ длина слова < минимальной → пропустить
    │       ├─ приложение в списке исключений → пропустить
    │       ├─ похоже на пароль, URL, email или путь → пропустить
    │       ├─ слово в списке исключений пользователя → пропустить
    │       │
    │       ├─ есть правило исправления опечатки → применить (без смены раскладки)
    │       │
    │       └─ триграммная модель языка сравнивает правдоподобие слова
    │           в текущей раскладке и его же в целевой
    │               │
    │               ├─ разница ниже порога → оставить как есть
    │               └─ выше порога → заменить и переключить раскладку
    │
    ├─ клик мышью / смена приложения → сброс буфера и контекста
    │
    └─ модификаторы (Cmd/Ctrl/Alt), Tab, Escape, стрелки → сброс буфера
```

Знаки препинания специально не считаются границей слова: на раскладке ЙЦУКЕН русские буквы б, ю, ж, э, х, ъ стоят там, где на QWERTY — знаки препинания. «Любовь», набранная в английской раскладке, выглядит как `k.,jdm` — точка и запятая здесь настоящие буквы слова, и обрывать по ним буфер нельзя.

### Как распознаётся неверная раскладка

Раньше распознавание строилось на доле нескольких десятков самых частых биграмм — грубая эвристика с заметным числом промахов на редких словах. Сейчас вместо неё — **символьная триграммная модель языка**: для английского и русского заранее (офлайн, `Tools/build_trigram_model.py`) по открытым частотным спискам слов посчитана таблица условных вероятностей «какая буква идёт после этих двух» и вшита в приложение как ресурс.

Для набранного слова модель считает, насколько правдоподобно оно выглядит на текущей раскладке, и насколько правдоподобно выглядит его перенос на другую раскладку через те же физические клавиши. Если перенос значительно правдоподобнее оригинала — раскладка перепутана. Пороги этого сравнения не подобраны на глаз, а измерены прогоном на размеченном корпусе слов.

Отдельно учитывается язык нескольких последних слов: часть пар вроде «руку» и «here» набираются абсолютно одинаковыми клавишами и в принципе неразличимы по одному слову — язык соседних слов в таких случаях единственная подсказка.

Системная проверка орфографии (`NSSpellChecker`) используется как страховка: если слово уже корректно на текущей раскладке, оно не трогается независимо от того, что говорит статистическая модель.

### Замена текста

Замена выполняется одной из четырёх стратегий, в зависимости от того, что поддерживает конкретное приложение — от мгновенной правки через Accessibility API до вставки через буфер обмена как самого надёжного, но самого тяжеловесного варианта. Приложение запоминает, какая стратегия сработала для каждой программы, и в следующий раз применяет её сразу, без перебора. Перед каждой заменой проверяется, что текст под курсором действительно тот, что ожидался (иначе клик мышью или автодополнение чужого приложения привели бы к порче случайного текста), и после замены — что она действительно применилась.

Буфер обмена при использовании этой стратегии — то есть в бэкенд-приложениях без другой альтернативы — восстанавливается сразу после вставки: то, что там лежало до замены, никуда не пропадает.

### Двойной Shift

Приложение отслеживает два последовательных нажатия Shift быстрее чем за 0.4 секунды. Если незадолго до этого (менее 5 секунд назад) было автопереключение — оно отменяется: возвращается исходное слово и раскладка.

### Словарь и обучение

`SwitchDictionary` хранится в `~/.switcher/dictionary.json` (pretty-printed JSON, стабильный diff, удобно для резервного копирования).

Содержимое:
- `exceptions` — слова, которые никогда не переключаются (массив, отсортированный для стабильного diff)
- `excludedApps` — bundle ID приложений-исключений
- `corrections` — правила замены опечаток: `[{from: "чтото", to: "что-то"}, ...]`

При включённом обучении отмена двойным Shift добавляет исходное слово в `exceptions` — в следующий раз оно не будет переключено автоматически.

## Настройки

Все настройки хранятся в `UserDefaults`. Словарь — отдельный JSON-файл (см. выше).

| Настройка | По умолчанию | Описание |
|---|---|---|
| Включить Switcher | вкл | Глобальный on/off, включает/останавливает event tap |
| Автопереключение | вкл | Переключение раскладки при вводе слова |
| Двойной Shift | вкл | Отмена последней автоматической замены |
| Минимальная длина слова | 4 | Слова короче не проверяются |
| Обучение | вкл | Накопление исключений и правил замены |
| Запускать при входе | выкл | Регистрация через `SMAppService.mainApp` |
