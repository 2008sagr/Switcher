# Переписывание ядра Switcher: детекция раскладки и замена текста

Дата: 2026-08-13
Статус: согласовано

## Задача

Switcher автоматически исправляет текст, набранный в неверной раскладке (EN ↔ RU),
без хоткеев. Текущая реализация работает нестабильно: движок периодически «залипает»
и теряет нажатия, замена текста иногда портит уже исправленный текст или соседние
слова, детекция даёт ложные срабатывания.

Цель — переписать ядро так, чтобы исправление было бесшовным: пользователь не должен
замечать механику, а ошибочное срабатывание не должно разрушать текст.

Область работ: детекция, замена текста, конвертация раскладок, жизненный цикл event tap.
UI, настройки и пользовательский словарь остаются как есть.

## Что не работает сейчас

### Блокер

Проект не собирается. В `Package.swift` цель `SwitcherCore` объявлена с
`path: "Sources/Switcher"`, а `executableTarget "Switcher"` без `path` claims тот же
каталог по умолчанию:

```
error: target 'Switcher' has overlapping sources: .../KeyboardEngine.swift, ...
```

Тесты в `Tests/SwitcherTests/` не собирались ни разу.

### Архитектура

**Блокирующий IPC в callback'е event tap на main thread.** `tryEarlySwitch()` вызывается
на каждом символе (`KeyboardEngine.swift:250`), внутри `isFocusedElementSecure()`
(`KeyboardEngine.swift:585`) делает два синхронных AX-запроса, плюс вызывается
`NSSpellChecker`. Дефолтный таймаут AX — 6 секунд. Пока callback не вернулся, ядро
держит все нажатия в системе; при превышении лимита система шлёт
`kCGEventTapDisabledByTimeout` и отключает тап. Это источник «залипаний» и потерянных
букв.

**Три конкурирующих пути детекции.** `tryEarlySwitch` (каждый символ), `tryPauseSwitch`
(таймер 0.3 с из `didSet` на `wordBuffer`), `triggerCheck` (пробел/Enter). Guard'ы
дублированы и рассогласованы: в `tryPauseSwitch` (`KeyboardEngine.swift:325-337`) один
и тот же набор проверок повторён трижды подряд. Таймер и space-триггер гоняются.

**`pendingEvents` небезопасен.** `KeyboardEngine.swift:171-176` сохраняет `CGEvent` за
пределы callback'а без `.copy()`; реплеит их без метки synthetic; реплеит
`flagsChanged`, чем ломает состояние модификаторов; постит в `.cghidEventTap`, поэтому
при смене приложения текст уходит не туда.

**Буфер символов вместо буфера keycode'ов.** Таблица на 70 пар в `LayoutConverter.swift`
зашита под QWERTY ↔ «Русская — ПК». На системной раскладке «Русская» знаки препинания
стоят на других клавишах, поэтому слова с `б ю ж э х ъ` конвертируются в мусор.

**Тап не слушает мышь.** Клик мышью перемещает каретку, `wordBuffer` остаётся старым,
и замена уничтожает не тот текст.

### Детекция

`ngramConfidence` (`SpellCheckService.swift:117`) считает долю биграмм, попавших в
захардкоженный список топ-40. Это не вероятность. Пороги `0.8 / 0.2` не обоснованы,
нормировки по длине нет, сглаживания нет, границы слова не учитываются.

Ранняя конверсия срабатывает по 4 символам — по префиксу такой длины слово неразличимо.

`NSSpellChecker.checkSpelling(language:)` молча деградирует без установленного словаря,
дорогой, и результат кэшируется навсегда без инвалидации.

### Замена текста

**Метка «своё событие» теряется.** `TextReplacer.swift:247` ставит магию на *событие*:
`event.setIntegerValueField(.eventSourceUserData, ...)`. Но `.eventSourceUserData` —
производное поле от источника события; при проходе через HID-тап система переписывает
его из источника. Когда метка теряется, собственный тап видит инжектированные символы
как пользовательский ввод, они падают в `wordBuffer`, и детектор срабатывает на уже
исправленном тексте. Это основная причина каскадных повторных конверсий.

**`.hidSystemState` наследует физическое состояние модификаторов.** Если в момент
инжекта пользователь ещё держит Shift, вставленные символы выходят в верхнем регистре.

**Постинг в `.cghidEventTap`** кладёт события в самый низ стека, и они проходят через
все тапы в системе, включая наш.

**Задержки на глазок.** `asyncAfter(count * 0.008 + 0.04)` между backspace'ами и
вставкой — окно, в которое влезают нажатия пользователя, автокоррекция macOS и
автодополнение приложения.

**`typeText` шлёт `2 × длина` событий** — keyDown+keyUp на каждый символ, с unicode-строкой
и на keyUp тоже, отчего часть приложений вставляет символ дважды. `virtualKey: 0` — это
`kVK_ANSI_A`; приложения, читающие keycode вместо unicode-строки (терминалы, Vim,
VS Code, игры), видят пачку нажатий «A».

**`replaceViaAXRange`** сравнивает `range.location >= original.count` в графемах, тогда
как AX-диапазоны считаются в UTF-16 (`TextReplacer.swift:109`). Верификация делается
сдвигом выделения с откатом (`TextReplacer.swift:113-124`), поэтому при неудачном
сравнении пользователь остаётся с выделенным куском текста.

**Восстановление буфера обмена через 0.6 с** (`TextReplacer.swift:173`) затирает то, что
пользователь скопировал в этот момент, и теряет нетекстовые типы данных.

**`TISSelectInputSource` вызывается параллельно с инжектом** (`KeyboardEngine.swift:370`) —
гонка между сменой раскладки и доставкой символов.

## Решения

### Согласованный объём

Включено:

- гибридный момент срабатывания: граница слова + пауза + ранняя конверсия при очень
  высокой уверенности;
- триграммная статистическая модель, вшитая в бандл, с генератором в репозитории;
- ручной список исключённых приложений (в настройках, уже существует);
- отмена исправления по double Shift;
- `UCKeyTranslate` для двух установленных источников ввода EN и RU;
- лёгкая эвристика пароля.

Не включено:

- одиночный Shift для смены языка (хватает системной комбинации);
- языки и раскладки кроме EN/RU;
- автодетект IDE/игр по `LSApplicationCategoryType`;
- вшитый полный словарь словоформ;
- отдельный механизм распознавания капчи (покрывается эвристикой пароля);
- настраиваемый хоткей отмены помимо double Shift.

### Поток обработки

```
[выделенный поток + свой CFRunLoop]
        CGEventTap callback          ~5 мкс, только работа с памятью
              │
              ├─ synthetic? → пропустить
              ├─ mouseDown / смена приложения / смена фокуса → сбросить буфер
              ├─ keyDown → дописать (keycode, flags, char) в KeystrokeBuffer
              └─ вернуть событие ВСЕГДА
                        │
                        ↓ async, serial queue
        LayoutDetector.evaluate(snapshot) → Verdict     ~50 мкс, чистая функция
                        │
                        ↓ main queue, если Verdict = .switch
        TextInjector.replace(...)
```

Три принципа:

**Callback никогда не подавляет клавишу.** Пробел проходит как есть; замена стирает
`слово + пробел` и вставляет `конвертированное + пробел`. Визуально результат тот же,
что у Punto и Caramba, но fast path становится тривиальным и физически не может съесть
нажатие. Это убирает весь класс гонок вокруг «проглотить и переклеить».

**Один путь детекции.** Чистая функция `LayoutDetector.evaluate(buffer, context) -> Verdict`
и три повода её позвать: граница слова, пауза 0.5 с, каждый символ при длине ≥ 5.
Guard'ы описаны в одном месте.

**AX только вне tap-потока и только с таймаутом.** `AXUIElementSetMessagingTimeout(element, 0.25)`.
Проверка на секретное поле кэшируется на фокус, а не выполняется на каждый символ.

Тап дополнительно слушает `mouseDown`, а `pendingEvents` хранит `CGEvent.copy()` с
жёстким лимитом окна 150 мс, после которого очередь сбрасывается безусловно.

### Детекция

Символьная триграммная модель с паддингом границ слова (`^^привет$`), сглаживание
Уиттена-Белла. Хранение — плоский бинарный ресурс `UInt32 ключ → Float16 log-вероятность`,
загрузка через `mmap`, поиск O(1).

Генератор — скрипт в репозитории, который один раз скачивает открытые частотные списки
EN/RU, строит таблицу и коммитит бинарный ресурс (~200–400 КБ на язык). В рантайме сети
нет, зависимости от системных словарей нет, поведение детерминированное.

Решение:

```
score_cur = model[EN].meanLogProb("ghbdtn")
score_tgt = model[RU].meanLogProb("привет")
switch if (score_tgt - score_cur) > threshold
```

Нормировка на длину убирает перекос в пользу коротких слов.

Поверх — словарный override: если слово валидно в текущем языке по `NSSpellChecker`,
не переключаем. Проверка уходит в фоновый поток, LRU-кэш получает TTL.

Ранняя конверсия использует ту же формулу, но префикс скорится без концевого маркера
(`^^ghbd` вместо `^^ghbd$`). Порог заметно выше обычного, минимальная длина — 5 символов.

Пороги калибруются тестом, а не назначаются: тест берёт списки слов EN/RU, транспонирует
их и меряет FP/FN по сетке порогов. Тест детерминированный и офлайновый.

### Guard'ы

- пользовательские исключения (слова);
- ручной список исключённых приложений по bundle ID;
- `AXSecureTextField` (асинхронно, с кэшем на фокус);
- URL, email, файловые пути;
- эвристика пароля: длина > 6 и одновременное присутствие строчных, заглавных и
  цифр/знаков → не трогаем. Закрывает пароли в терминале (`sudo`), поля Electron и
  капчи, где `AXSecureTextField` не срабатывает;
- сброс буфера по: mouseDown, смене приложения, смене фокуса, стрелкам, Tab, Escape,
  комбинациям с Cmd/Ctrl/Opt.

### Конвертация раскладок

`LayoutMapper` строит таблицу соответствий через `UCKeyTranslate` по данным
`kTISPropertyUnicodeKeyLayoutData` двух выбранных источников ввода (EN и RU). Это
корректно обрабатывает обе системные русские раскладки — «Русская» и «Русская — ПК» —
у которых знаки препинания стоят на разных клавишах.

Таблица перестраивается по уведомлению о смене набора установленных источников ввода.

### Замена текста

Принцип: перед каждой мутацией и после неё состояние подтверждается.

#### Хвостовой символ

Замена запускается тремя поводами, и они отличаются тем, что стоит после слова:

- граница слова — пользователь уже нажал пробел или пунктуацию, символ доставлен,
  `tail = 1`;
- пауза 0.5 с и ранняя конверсия — после слова ничего нет, `tail = 0`.

Везде ниже `tail` — длина этого хвоста в UTF-16, `wordLen` — длина слова в UTF-16.
Хвост входит в проверяемый и в стираемый диапазон, но не в конвертируемый: он
переносится в замену как есть.

#### Pre-flight

```
1. читаем AXSelectedTextRange → (loc, len)     [UTF-16]
2. guard len == 0 (курсор, а не выделение)
3. start = loc - wordLen - tail
   guard start >= 0                            (слово в начале поля — выходим)
4. textBehind = AXStringForRange(start, wordLen + tail)
5. textBehind == "ghbdtn " ? → да: работаем. нет: молча выходим.
```

Шаг 4 закрывает клик мышью между набором и заменой, автодополнение приложения,
допечатывание пользователем во время окна и протухший буфер после смены фокуса. Если
текст под кареткой не тот, что ожидался, замена не выполняется вообще.

`AXStringForRange` — параметризованный атрибут, читает не двигая выделение.

Если AX недоступен и проверить нечем, замена выполняется только при свежем буфере:
не было событий мыши, не было смены фокуса, последнее нажатие менее 2 с назад.

#### Стратегия A — прямая правка через AX

```
6. AXSelectedTextRange = (start, wordLen)        // хвост не трогаем
7. AXSelectedText      = "привет"
8. AXSelectedTextRange = (start + replacementLen, 0)
9. пост-проверка: AXStringForRange(start, replacementLen + tail) == "привет "
```

Ноль синтетических событий, ноль таймеров, ноль работы с буфером обмена. Целевые
приложения: нативные AppKit/SwiftUI, Notes, Mail, Xcode, Safari, поля Slack.

#### Стратегия B — переигрывание keycode'ов

Для приложений, читающих keycode вместо unicode-строки события: терминалы, Vim в
терминале, VS Code, Electron с перехватом клавиш, игры.

```
1. TISSelectInputSource(ru)
2. ждём DistributedNotification TISNotifySelectedKeyboardInputSourceChanged
3. backspace × (wordLen + tail)
4. переигрываем записанные keycode'ы слова с исходными флагами
5. переигрываем keycode хвоста, если tail == 1
```

Приложение само отрисовывает нажатия через уже активную раскладку. Шаг 2 — ожидание
системного уведомления, не таймер.

#### Стратегия C — выделение и одна вставка

```
1. Shift+← × (wordLen + tail), одной пачкой, один источник
2. проверка: AXSelectedText == "ghbdtn " (чтение AX часто доступно там, где запись нет)
3. одно событие с полной строкой "привет " в keyboardSetUnicodeString
```

`keyboardSetUnicodeString` принимает строку целиком. Одно событие → один `insertText` в
приложении → атомарно, один шаг undo, между символами нечему разъехаться.

#### Стратегия D — буфер обмена

Последний резерв. `ClipboardGuard` снимает все `pasteboardItems` со всеми типами данных
и восстанавливает содержимое только если `changeCount` равен тому, что мы оставили после
своей записи. Если между записью и восстановлением в буфер писал кто-то ещё, содержимое
не трогаем.

#### Общие правила инжекта

Один общий источник событий на всё приложение, создаётся один раз:

```swift
let injectSource = CGEventSource(stateID: .privateState)!
CGEventSourceSetUserData(injectSource, Self.magic)   // на ИСТОЧНИК, не на событие
```

Проверка в тапе — по `.eventSourceUserData`. Изнутри callback'а события постятся через
`CGEvent.tapPostEvent(proxy)`: событие вставляется после нашего тапа в цепочке и
структурно не может вернуться к нам.

`.privateState` вместо `.hidSystemState` даёт независимое состояние модификаторов.

Ни в одной стратегии нет `asyncAfter` с угаданным числом. Переходы — синхронные
AX-вызовы с таймаутом 0.25 с, ожидание системного уведомления, либо гарантированный
порядок доставки внутри одного `CGEventSource`.

#### Кэш возможностей приложения

```
[com.googlecode.iterm2]  → .keycodeReplay
[com.apple.Notes]        → .axDirect
[com.tinyspeck.slackmac] → .selectAndInject
```

Первое переключение в незнакомом приложении пробует стратегии по порядку и запоминает
победившую; дальше идёт сразу в неё. Пост-проверка делает кэш самовосстанавливающимся:
если стратегия перестала работать после обновления приложения, она понижается
автоматически.

| Класс приложения | Стратегия | Событий |
|---|---|---|
| Нативные (Notes, Mail, Xcode, Safari) | A — AX-диапазон | 0 |
| Терминалы, игры, VS Code | B — переигрывание keycode'ов | 2N+2 |
| Electron/Chromium с текстовыми полями | C — выделение и одна вставка | N+1 |
| Всё остальное | D — буфер обмена | 4 |

## Структура кода

`KeyboardEngine.swift` (632 строки) разбирается на единицы с одной ответственностью:

| Файл | Ответственность |
|---|---|
| `Input/EventTapController` | жизненный цикл тапа, выделенный поток, re-enable по timeout |
| `Input/KeystrokeBuffer` | буфер нажатий, границы слов, откат по backspace |
| `Detection/TrigramModel` | загрузка ресурса, `meanLogProb` |
| `Detection/LayoutDetector` | вердикт, чистая функция |
| `Detection/GuardRules` | исключения, приложения, URL/email, пароли, секретные поля |
| `Replacement/TextInjector` | четыре стратегии, кэш возможностей |
| `Replacement/ClipboardGuard` | безопасный снимок и восстановление pasteboard |
| `Layout/LayoutMapper` | EN↔RU через `UCKeyTranslate` |
| `SwitchCoordinator` | оркестрация, undo, double Shift |

Остаются без изменений: `AppState`, `SwitchDictionary`, `SettingsView`,
`MenuBarContentView`, `InputSourceManager`.

## Тестирование

`Package.swift` чинится: у `executableTarget "Switcher"` появляется собственный путь,
пересечение исходников устраняется.

Автотесты (без Accessibility, детерминированные):

- `LayoutMapper` — round-trip конвертации для обеих русских раскладок, знаки препинания,
  регистр;
- `TrigramModel` — загрузка ресурса, `meanLogProb` на эталонных словах;
- `LayoutDetector` — калибровочный корпус: списки слов EN/RU, транспонированные в другую
  раскладку; измеряются FP/FN по сетке порогов, фиксируются регрессионные границы;
- `GuardRules` — URL, email, пути, эвристика пароля, исключения;
- `KeystrokeBuffer` — накопление, backspace, сброс по событиям.

Три существующих теста переписываются под новые API.

Ручная проверка (требует Accessibility):

- по одному приложению на каждый класс из таблицы стратегий;
- поля паролей, `sudo` в терминале;
- исключённые приложения;
- double Shift на выделении и без;
- сохранность буфера обмена при срабатывании стратегии D.

## Критерии готовности

- `swift build` и `swift test` проходят;
- ни одного блокирующего вызова в callback'е event tap;
- ни одного `asyncAfter` с угаданной задержкой на пути замены;
- каждая замена предваряется проверкой текста под кареткой и завершается пост-проверкой;
- пороги детекции получены из калибровочного теста, а не назначены вручную;
- слова с `б ю ж э х ъ` корректно конвертируются на обеих системных русских раскладках.
